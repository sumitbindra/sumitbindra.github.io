Multi-Agent LLM Systems

ouroAI: Multi-Agent CRM Automation Platform

Problem: Real-estate and sales teams need intelligent automation that can handle SMS, email, WhatsApp, and voice outreach while maintaining context and knowing when to escalate to humans.

What I Built: A Gemini-orchestrated multi-agent platform where four specialized tool-calling agents (query, outreach, sync, reporting) coordinate across communication channels. Replaced a hand-written 3-call prompt chain with a DSPy ChainOfThought pipeline optimized with BootstrapFewShot on 89 labeled conversations, achieving 88.9% accuracy on a held-out validation set. Implemented hybrid retrieval (Gemini embeddings + BM25) over CRM contacts and per-account knowledge bases synced to voice agents.

Stack: React, TypeScript, FastAPI, Supabase (Postgres with pgvector, Auth, RLS multi-tenancy), Docker, Railway. 238 commits, 28+ PRs, 50+ pytest files plus Vitest and Playwright E2E tests.

AI Voice Call Scheduler with ElevenLabs & Twilio

Problem: Businesses need intelligent voice agents that can handle inbound and outbound calls, schedule appointments, handle voicemails, and sync with CRMs—without human intervention for routine calls.

What I Built: Inbound and outbound voice agents on ElevenLabs Conversational AI integrated with Twilio phone numbers. Signature-verified FastAPI webhooks handle scheduling logic, voicemail auto-reschedule, and CRM booking via server tools. Gemini analyzes each transcript for summary, sentiment, action items, and reschedule intent.

Stack: ElevenLabs Conversational AI, Twilio, FastAPI, Gemini, webhook authentication, CRM integrations.

CICA: Construction & Insurance Document AI

Problem: Commercial insurance underwriting and construction bidding require extracting structured data from complex documents (bid forms, specifications, proposals) and identifying financial, schedule, scope, and legal discrepancies.

What I Built: Structured extraction pipeline using OpenAI/Gemini with Pydantic/JSON-schema validation, LlamaIndex RAG, Azure Document Intelligence, and Reducto parsing. Built an LLM-judged evaluation harness to measure extraction accuracy and discrepancy detection across document types.

Stack: OpenAI, Gemini, Pydantic, LlamaIndex, Azure Document Intelligence, Reducto, LLM-based eval framework.

AI × Transportation

LLM-Driven Four-Step Travel Demand Model

Problem: Traditional travel demand models require extensive calibration of hundreds of coefficients. Can LLMs replace estimated parameters with reasoning-based decision-making?

What I Built: A four-step travel demand model where trip generation, distribution, and mode choice are answered by an LLM decision engine instead of calibrated coefficients. Validated on Sioux Falls against ACS, LODES, NHTS, and traffic counts; compared with a conventional gravity/MNL model (67 coefficients) under transit, parking, and capacity policy scenarios. Engineered reproducible experiments with hash-keyed SQLite request cache, cost guard with dry-run, placebo-controlled prompt-framing tests, temperature scaling, and calibration ladder. Abstract submitted to Modeling Mobility (MoMo) 2027.

Stack: Python, LLM API (temperature scaling, structured outputs), SQLite, pytest (26 test files, 171 commits).

tdm-platform: Closed-Loop Travel Demand Model on Serverless Compute

Problem: Activity-based travel models are compute-intensive, region-specific, and expensive to run. How can we make them portable and affordable?

What I Built: Region-agnostic platform combining ActivitySim and AequilibraE (Frank-Wolfe user-equilibrium assignment with skim feedback) that builds a model region from open OSM/TIGER data. Demo region: 168 TAZs, 73k links. Runs on Modal serverless compute for approximately $0.07 per scenario.

Stack: Python, ActivitySim, AequilibraE, OSM/TIGER data processing, Modal serverless.

travel-mcp-server: MCP Server for Travel Model Outputs

Problem: LLM applications need structured access to travel model outputs (trip tables, skims, network data) stored in domain-specific formats like Parquet and OMX.

What I Built: Model Context Protocol (MCP) server with 8 tools that let LLM clients query travel model outputs using DuckDB SQL, pull trip statistics and skims, and generate charts. Packaged in Docker for easy deployment.

Stack: Python, MCP, DuckDB, Parquet, OMX, Docker.

Other AI Applications
